# 9.4 VPS preparation runbook

This runbook prepares configuration and commands only. It does not execute
against a VPS, use Docker/MongoDB locally, modify Nginx, or publish a release.

## Nginx staging and validation

The candidate routing template is
`deploy/nginx/souqak-seo.conf.template`. It does not contain a secret or a live
host certificate. Merge only the routing directives into the reviewed existing
HTTPS server block. Preserve existing TLS, security, rate-limit, WebSocket,
API, PWA, and `apps.souqak-yem.com` configuration.

Before staging, discover the exact active Nginx config rather than assuming a
single file:

```bash
sudo nginx -T > /tmp/souqak-nginx-before.txt
sudo readlink -f /etc/nginx/sites-enabled/*
sudo grep -RIl 'souqak-yem\.com' /etc/nginx/sites-enabled /etc/nginx/conf.d 2>/dev/null
```

Stage and test an immutable candidate only after identifying the actual file:

```bash
sudo cp --preserve=mode,ownership,timestamps \
  /etc/nginx/sites-available/souqak-yem.conf \
  /var/backups/souqak/9.4/nginx.before.conf
sudo install -o root -g root -m 0600 \
  deploy/nginx/souqak-seo.conf.template \
  /etc/nginx/sites-available/souqak-yem.conf.candidate
sudo nginx -t
```

Do not replace or reload the active config until Backend and Frontend readiness
and a protected activation dry-run have succeeded.

Routing order:

1. Exact `robots.txt` and `sitemap.xml` to loopback Backend.
2. Dynamic `/ad`, `/category`, `/store`, `/auctions/:id` paths to loopback Backend.
3. Existing `/api/`, `/uploads/`, and `/socket.io/` paths remain loopback Backend.
4. `/assets/` is served only from the managed Frontend.
5. Static SPA fallback remains `try_files $uri $uri/ /index.html`.
6. Host canonicalization is apex HTTPS. Referral and tracking query strings are
   preserved during host/trailing-slash handling.
7. PWA/app subdomains and their application routes are unchanged.

## Protected execution sequence

The Git branch must be merged to `main` only after owner approval. Do not run
the convenience activation command for this phase without the owner-authorized
candidate SHA.

```bash
RELEASE=c4cd385d041d01c2d46652647f8c39e1b8e805a4

# 1. Prepare only the explicit SHA.
sudo -n /usr/local/libexec/souqak/prepare-update.py --prepare "$RELEASE"

# 2. Review local/protected evidence, manifest, Snapshot and receipts.
sudo ls -l "/home/souqak/deploy/prepared/$RELEASE"
sudo cat "/home/souqak/deploy/prepared/$RELEASE/manifest.json"

# 3. Dry-run activation.
sudo -n /usr/local/libexec/souqak/activate-release.py \
  --dry-run \
  --release "$RELEASE" \
  --bundle "/home/souqak/deploy/prepared/$RELEASE"

# 4. Activate only after explicit operator approval.
sudo -n /usr/local/libexec/souqak/activate-release.py \
  --release "$RELEASE" \
  --bundle "/home/souqak/deploy/prepared/$RELEASE"

# 5. Backend/Frontend readiness (after activation helper succeeds).
curl --fail --show-error --silent --head \
  http://127.0.0.1:5000/api/health/readiness
curl --fail --show-error --silent \
  https://souqak-yem.com/souqak-release.txt

# 6. Apply staged Nginx config only after readiness.
sudo nginx -t
sudo systemctl reload nginx
sudo nginx -t
```

`nginx -t` must succeed before activation and again before reload. Activation
normally must not be followed by Nginx edits unless the readiness review
requires the separately staged SEO routing change.

## Rollback

Pass the currently active release SHA, not a guessed previous commit:

```bash
sudo -n /usr/local/libexec/souqak/activate-release.py \
  --dry-run \
  --rollback \
  --release "<currently-active-full-commit-sha>"

sudo -n /usr/local/libexec/souqak/activate-release.py \
  --rollback \
  --release "<currently-active-full-commit-sha>"
```

Protected rollback restores the recorded Backend and Frontend and does not
restore MongoDB or uploads. If Nginx was changed independently, restore only
the exact backed-up Nginx file, validate it, then reload:

```bash
sudo tar -C / -xpf /var/backups/souqak/9.4/<stamp>/nginx.tar
sudo nginx -t
sudo systemctl reload nginx
```

Restore env only as a separate approved rollback operation, using the exact
backed-up file and preserving root access:

```bash
sudo install -o souqak -g souqak -m 0600 \
  /var/backups/souqak/9.4/<stamp>/env.souqak \
  /home/souqak/deploy/souqak/.env
```

Restore tools only if the VPS tool change itself is being rolled back:

```bash
sudo install -o root -g root -m 0755 \
  /var/backups/souqak/9.4/<stamp>/souqak-update \
```
